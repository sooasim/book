# 크롬 확장 자동 채우기 (기본정보 1회 저장 → 방문 사이트 자동 인식·채움)

작성일: 2026-06-14
구현체: `apps/ebook_publisher/chrome_extension/` · 단일 소스: `resources/field_keywords.json`

---

## 1. 요청 → 구현

> "크롬 플러그인이나 매크로처럼, 출간에 필요한 정보를 미리 입력·저장해 두고, 방문하는 사이트
> 페이지의 입력란을 자동 인식하여 자동 채우기를 실행"

→ **크롬 확장(Manifest V3)** 으로 구현. 사이트별 스크립트 없이, 어떤 출판 사이트든 페이지의
입력칸을 휴리스틱으로 인식해 저장된 기본정보로 채운다.

| 요청 요소 | 구현 |
|---|---|
| 출간 정보 미리 입력·저장 | 옵션 페이지 → `chrome.storage.local`(oces_profile) |
| 방문 사이트 입력란 자동 인식 | `content.js` DOM 스캔 + `fieldmatch.js` 휴리스틱(한/영) |
| 자동 채우기 실행 | 플로팅 "📚 자동 채우기" 버튼 / 팝업 버튼 |
| 매크로 대비 안전 | 민감칸·약관·캡차·제출 버튼은 절대 자동 처리 안 함 |

## 2. 동작

1. 기본정보 1회 저장(옵션) → 2. 출판 사이트 로그인(직접) → 3. 등록 폼 페이지에서 버튼 클릭 →
4. 텍스트 칸 자동 채움(초록), 파일 칸은 직접 첨부 안내(노랑) → 5. 약관·인증·최종 게시는 사람.

## 3. 안전 설계

- `field_keywords.json`의 **민감어(33개)**(password/비밀번호/captcha/인증번호/카드/계좌/주민/사업자/세금 등)
  에 매칭되면 `guessFieldKey`가 `null` → 절대 채우지 않음.
- 체크박스·라디오·submit·button·password 타입은 스캔 대상에서 제외.
- 파일 입력은 브라우저 보안상 값 설정 불가 → 강조 표시만(사람이 첨부).
- 제출/약관/본인인증/최종 게시는 코드가 클릭하지 않음.

## 4. 휴리스틱 단일 소스 + 동기화

필드 인식 규칙은 Selenium 봇의 `inspector.py`와 **동일한 `resources/field_keywords.json`** 을 사용한다.
- 생성: `inspector.FIELD_KEYWORDS` → `resources/field_keywords.json` → 확장에 복사.
- 강제: `selenium_bot/tests/test_field_keywords_parity.py`가 셋의 동일성을 검증.

## 5. 테스트

- JS: `node apps/ebook_publisher/chrome_extension/tests/fieldmatch.test.js` (7 케이스: 한/영 인식, 민감 차단, buildFillPlan).
- Python: 파리티 테스트(휴리스틱 동기화) — selenium_bot 스위트에 포함.

## 6. 두 자동화 경로의 관계

| | 크롬 확장 | Selenium 봇 |
|---|---|---|
| 용도 | 사람이 보는 브라우저에서 즉석 자동 채움 | 스크립트로 계획 실행·일괄/반복 |
| 설치 | 크롬에 unpacked 로드 | 로컬 python + selenium |
| 세션 | 사용자의 기존 크롬 로그인 사용 | 플랫폼별 영속 프로필 |
| 공통 | 동일 필드 휴리스틱·동일 안전 게이트(최종 게시는 사람) | |
