# 스튜디오 ↔ 크롬 확장 연동 · 파일 첨부 가이드

작성일: 2026-06-15

---

## 1. 스튜디오 → 확장 기본정보 1클릭 이전

스튜디오(OCES)에서 만든 책 메타데이터를 크롬 확장의 기본정보로 그대로 옮긴다.

- 백엔드: `GET /api/projects/{id}/extension-profile` → 확장 `oces_profile` 형태 JSON 반환
  (service.`export_extension_profile`). 제목·저자·언어·소개(챕터 본문에서 추출)·키워드 등.
  민감정보는 포함하지 않음.
- 확장: 옵션 페이지에 **JSON 가져오기 / 내보내기** 추가.
  스튜디오 JSON 을 붙여넣고 [가져오기] → `chrome.storage.local` 저장 → 모든 사이트 자동 채움에 사용.
- 정규화: `profileio.normalizeProfile` 가 허용 키만 통과시키고 민감 키(비번/세금/계좌/카드/주민/사업자 등)는 제거.

## 2. 소개문 추출 규칙

`export_extension_profile` 의 `description` 은 **챕터 본문(서론 등)** 에서 추출한다(조판 프런트매터·헤딩 제외).
이전엔 윤문본 전체에서 뽑아 판권/목차가 섞였으나, 챕터 `content_md` 기반으로 교정함.

## 3. 파일 첨부 가이드 오버레이

브라우저 보안상 확장은 파일 입력값을 설정할 수 없다. 그래서 `content.js` 가
원고/표지 파일 입력칸을 감지하면 그 옆에 **"📎 여기에 원고(EPUB/PDF) 첨부" / "🖼 여기에 표지 첨부"**
안내 배지를 띄워 사용자가 직접 첨부하도록 돕는다(노란 배지 + 외곽선).

## 4. 테스트

- JS: `fieldmatch.test.js`(11) + `profileio.test.js`(6) — 허용/민감 키, keywords 정규화, parseImport 예외.
- Python: `test_extension_profile.py` — export 형태/소개문 헤딩 제외/미존재 프로젝트.

## 5. 사용 흐름

1. 스튜디오에서 책 생성(compose) → `GET /api/projects/{id}/extension-profile` JSON 복사.
2. 확장 옵션 → [JSON 가져오기] 붙여넣기 → 저장.
3. 출판 사이트 폼에서 자동 채우기(텍스트) + 파일 칸은 안내 배지대로 직접 첨부 → 최종 게시는 사람.
