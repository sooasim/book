# OneClick eBook Studio — 기술 백서 (Technical White Paper)

문서 버전: 1.0 · 상태: Draft · 기준: 리포지토리 v0 스켈레톤

---

## 1. 요약 (Executive Summary)

OCES는 **자연어 입력(제목·주제)만으로 출판 가능한 수준의 전자책을 자동 생성**하는 SaaS이다.
저자는 한 권을 쓰는 데 수백 시간을 쓰지만, OCES는 AI 오케스트레이션을 통해 **초안 한 권을 수십 분 내**에 산출하고,
사람은 *검수·교정·취향 반영*이라는 고부가가치 작업에만 집중한다.

핵심은 "한 번의 LLM 호출로 책을 뽑는" 단순 생성이 아니라, **다단계 에이전트 파이프라인 + 일관성 제어 + 품질 게이트**를 갖춘
프로덕션 시스템이라는 점이다.

## 2. 문제 정의 (Problem)

- **시간/비용**: 비소설(실용서/가이드/사내문서/리드매그닛) 한 권 집필에 평균 100~400시간.
- **일관성 붕괴**: 긴 글일수록 용어·톤·구조·사실의 일관성이 무너진다. 단순 LLM 생성의 최대 약점.
- **조판/출간 장벽**: 원고가 있어도 EPUB/PDF 변환, 목차/각주/이미지 배치, 스토어 메타데이터 작성은 별도 전문 작업.
- **품질 신뢰**: 환각(hallucination), 표절, 사실 오류로 인해 "AI 생성물"은 그대로 출판하기 어렵다.

## 3. 제품 비전 (Vision)

> "주제를 가진 누구나, 클릭 한 번으로 검수 가능한 책 초안과 출판 파일을 손에 쥔다."

대상 콘텐츠: 실용서, 기술 가이드, 교육 교재, 기업 백서/매뉴얼, 뉴스레터 합본, 리드 마그넷(lead magnet) eBook.
(순수 창작 소설은 v2+ 확장 영역으로 둔다 — 플롯/캐릭터 일관성은 별도 난제.)

## 4. 가치 제안 (Value Proposition)

| 사용자 | 기존 | OCES |
|--------|------|------|
| 1인 창작자/코치 | 수개월 집필 | 수십 분 초안 + 반나절 검수 |
| 마케터 | 외주 비용 수백만원 | 셀프 서비스로 리드 마그넷 양산 |
| 기업 | 매뉴얼 작성 인건비 | 사내 지식 → 표준 문서 자동화 |
| 출판 기획자 | 기획-집필 리드타임 | 빠른 컨셉 검증(초안 A/B) |

## 5. 차별점 (Differentiation)

1. **오케스트레이션 우선 설계** — 목차/집필/교정/조판이 분리된 단계 에이전트로 구성되어 단계별 재생성·개입이 가능.
2. **일관성 엔진** — Style Bible(용어·톤·페르소나) + 챕터 간 컨텍스트 요약 캐리오버 + RAG 사실 고정.
3. **품질 게이트** — 사실검증/표절/가독성/금칙어 자동 검사 통과해야 다음 단계로 진행(상태머신).
4. **출판 파이프라인 내장** — Markdown 단일 소스(SSOT) → EPUB/PDF/DOCX/HTML 멀티 렌더.
5. **모델 독립성** — LLM Provider 추상화로 비용/품질 트레이드오프 선택 가능.

## 7. 기술 스택 근거 (Stack Rationale)

| 영역 | 선택 | 이유 |
|------|------|------|
| API | **FastAPI (Python 3.11)** | 비동기, 타입(pydantic), LLM/ML 생태계 근접 (현 리포 채택) |
| Web | **Next.js 16 / React 19** | App Router, SSR/스트리밍 UI, SSE 친화 (현 리포 채택) |
| 잡 큐 | **Redis + RQ/Celery 또는 Arq** | 장시간 비동기 작업, 재시도/멱등성 |
| DB | **PostgreSQL** | 프로젝트/잡/사용자 영속화, JSONB로 유연한 메타 |
| 벡터DB | **pgvector 또는 Qdrant** | RAG 사실 고정, 챕터 간 의미 검색 |
| 스토리지 | **S3 호환 (R2/MinIO)** | 산출물(EPUB/PDF/이미지) 보관 |
| LLM | **Anthropic Claude(권장) + Provider 추상화** | 장문 일관성/지시 준수 강점, 교체 가능 설계 |
| 배포 | **Docker / Railway(현재) → K8s 확장** | 현 리포 Dockerfile·Railway 핀 반영 |

## 8. 리스크 및 완화 (Risks & Mitigations)

| 리스크 | 영향 | 완화 |
|--------|------|------|
| 환각/사실 오류 | 신뢰도 | RAG 근거 인용 강제 + Fact-check 게이트 + HITL 검수 |
| 표절/저작권 | 법적 | 표절 검사(임베딩 유사도 + 외부 API), 출처 명시, 학습데이터 면책 |
| 비용 폭증(토큰) | 단가 | 단계별 모델 티어링, 캐싱, 컨텍스트 압축, 토큰 예산 가드 |
| 장시간 작업 실패 | UX | 상태머신 + 멱등 단계 + 체크포인트 재개(resume) |
| 일관성 붕괴 | 품질 | Style Bible + 컨텍스트 캐리오버 + 전역 교정 패스 |
| 모델 종속 | 운영 | Provider 추상화 + 폴백 라우팅 |

## 9. 성공 지표 (KPI)

- **TTFD (Time-To-First-Draft)**: 1만 단어 기준 P50 < 20분.
- **검수 후 출판률**: 생성 초안 중 사람이 출판까지 끌고 간 비율 ≥ 40%.
- **일관성 점수**: 자동 평가(용어/톤/구조) ≥ 0.85.
- **단계 재생성률**: 단계별 재시도 평균 < 1.5회.
- **토큰 단가/권**: 목표 비용 상한 내 유지.

## 10. 로드맵 요약

- **v0 (현재)**: 스켈레톤 — API 스텁 + Web 스캐폴드.
- **v1 (MVP)**: 제목·주제 → 목차 → 본문 → Markdown/EPUB 다운로드 (동기 단순 파이프라인).
- **v2**: 잡 큐 비동기화, 진행 스트리밍, 단계별 재생성, 품질 게이트, PDF.
- **v3**: RAG 자료 업로드, 이미지 생성, 스타일 바이블 UI, 협업/버전관리.
- **v4**: 멀티유저 SaaS(결제/쿼터), 스토어 메타데이터, 다국어/번역.
