## 0. 이 문서의 위치

- v1(`00`~`05`): 윤문기·출판 파이프라인 기본 설계 + 600항목 필수 체크리스트.
- v2(`06`): 제로존 방법론(7-에이전시, 정직 봉인, Lemma, Hard-Fail).
- **v3.0(본 문서)**: 첨부된 `Ebook Polisher` 기술백서 + `AutoBook` 참조 아키텍처의 검증된 패턴을 흡수하여
  **3000페이지 이상 장편을 누락 0으로 처리하는 원장(Ledger) 기반 무손실 엔진**으로 확정한다.
  v1·v2의 모든 게이트(600 체크리스트, Hard-Fail, 정직 봉인)는 v3 파이프라인의 단계 게이트로 흡수된다.

> 핵심 명제: **"긴 컨텍스트 모델 하나에 맡기지 않는다. 문서를 페이지·블록 원장으로 만들고, 청크는 작업 단위로만 쓰며, 모든 결과를 block_id 기준으로 되돌려 받는다."**

## 1. 4대 불변 원칙 (Invariants)

1. **페이지 원장 우선**: 모든 작업의 기준은 Page Ledger. AI 처리 단위는 청크여도 **검증 단위는 페이지/블록**.
2. **청크=작업 단위, 페이지=책임 단위**: 윤문 요청은 청크로 보내되, 검증은 페이지·블록으로 되쪼갠다.
3. **AI 출력은 계약**: 자유 문장 금지. `block_id`를 보존한 구조화 출력(JSON Schema)만 허용.
4. **Coverage Gate**: `source = parsed = chunked = polished = verified = assembled` 페이지 수가 전부 일치해야 출력 가능. 하나라도 어긋나면 출력 버튼 비활성화.

## 2. 핵심 문제와 해법 매핑

| 장편 원고의 실제 문제 | v3 해법 |
|---|---|
| 페이지/장/절/문단/문장이 안정적으로 식별 안 됨 | Structure Tree + Page/Block 원장 |
| 청크 분할 시 맥락·용어·인물 약화 | 세 겹 컨텍스트(로컬·구조·전역) + Style Bible + 전역 메모리 |
| 병렬 처리 시 청크별 문체 불일치 | Style Drift Detector + Consistency Pass |
| 페이지/문단 누락을 즉시 못 알아챔 | Coverage Gate + Block Hash Verification |
| AI가 무단 요약·구조 변경 | 구조화 출력 계약 + Semantic Preservation + 금지 변경 검사 |
| 병합 시 순서·각주·표·수식 어긋남 | block_id 기준 재조립 + 출판 전 QA 14게이트 |

## 3. 전체 아키텍처

```mermaid
flowchart TD
    A[원고 업로드 PDF/DOCX/TXT/EPUB] --> B[포맷 감지·원본 해시 보존]
    B --> C[문서 파서]
    C --> D[Page Ledger]
    C --> E[Structure Tree]
    D --> F[Block/Sentence 원장]
    E --> G[Ledger-Aware 청킹]
    F --> G
    G --> H[Coverage: chunk plan 검증]
    H --> I[컨텍스트 패키저(3겹)]
    I --> J[윤문 워커 / 7-Agency 토론]
    J --> K[구조화 출력 검증(block_id 보존)]
    K --> L[누락/변형/금지변경/정직봉인 감사]
    L --> M{게이트 통과?}
    M -- 아니오 --> N[보수 프롬프트·재시도(해당 블록만)]
    N --> J
    M -- 예 --> O[결과 원장 저장 + 감사 로그]
    O --> P[전역 Consistency Pass + Style Drift]
    P --> Q[최종 재조립(block_id 순서)]
    Q --> R[출판 전 QA 14게이트 + 600 체크리스트]
    R --> S[DOCX/EPUB/MD/PDF 출력]
```

## 4. 데이터 모델 (원장)

구현: [`apps/ebook_polisher/ebook_polisher/models.py`](../apps/ebook_polisher/ebook_polisher/models.py), 스키마: `schema.sql`.

| 모델 | 핵심 필드 | 책임 |
|---|---|---|
| `Book` | book_id, title, author, genre, language, source_format, source_hash | 작품 단위 |
| `Page` | page_id, page_number, chapter_id, raw/normalized_text, source_hash, output_hash, status | **책임 단위** |
| `Block` | block_id, page_id, order_index, block_type, raw_text, polished_text, source_hash, status | 최소 추적 단위 |
| `Chunk` | chunk_id, primary_block_ids, overlap_block_ids, page_start/end, token_estimate, status | **작업 단위** |

`block_type ∈ {title, paragraph, quote, footnote, table, formula, caption}`.

## 5. 처리 파이프라인 (단계 게이트)

| 단계 | 입력 | 산출 | 게이트 |
|---|---|---|---|
| Ingest | 파일 | 원본 보존 + 포맷 | 해시 기록 |
| Normalize | raw | NFC·공백·OCR·머리/꼬리글 분리 | — |
| Structure | 정규화 텍스트 | Book→Part→Chapter→Section→Page→Block→Sentence | 규칙 우선, LLM은 검증만 |
| Style Bible | 책 메타·표본 | 장르/말투/용어/금지변경 규칙 | 사람 확인 |
| Chunk Plan | blocks | chunk list + coverage map | **chunk coverage OK** |
| Polish | 청크+3겹 컨텍스트 | PolishedBlock[] | 구조화 출력 계약 |
| Verify | 출력 | 누락/금지변경/의미보존/정직봉인 | **block coverage OK** |
| Consistency | 전권 | 용어/인물/말투/번호 정합 | drift 임계 이하 |
| Assemble | polished blocks | 재조립 원고 | **page coverage OK** |
| QA | 원고 | 14게이트 + 600 체크리스트 + Hard-Fail | **전부 PASS** |
| Export | 원고 | DOCX/EPUB/MD/PDF | 해시·감사 저장 |

### 5.1 세 겹 컨텍스트
1. **로컬**: 현재 청크 앞뒤 겹침 문단(overlap).
2. **구조**: 장/절 제목, 현재 위치, 앞/뒤 장 요약.
3. **전역**: 용어집·인물표·문체 규칙·금지 변경 목록(전역 메모리에서 라우팅).

## 6. 청킹 알고리즘 (Ledger-Aware)

구현: [`chunker.py`](../apps/ebook_polisher/ebook_polisher/chunker.py).

- 토큰 예산 이하 + 문단 중간 절단 최소화 + 페이지 경계 보존 + 앞뒤 오버랩 + 장/절 제목 포함 + 포함 block_id 전부 기록.
- **Adaptive Boundary Score**: `0.30·heading + 0.20·page + 0.20·semantic_shift + 0.15·para_balance + 0.10·scene + 0.05·(−table/formula 절단 패널티)`.
- **빠짐 방지**: 모든 block은 최소 1회 *primary* chunk에 포함. overlap에만 든 block은 미처리로 간주.

토큰 예산 표(컨텍스트별 본문/오버랩/규칙/출력여유): 32k→12k/2k/4k/8k · 128k→50k/8k/12k/32k · 1M→200k/30k/40k/200k.
1M 컨텍스트라도 원장·청크 검증은 유지한다(긴 컨텍스트는 안전장치가 아니라 편의장치).

## 7. 검증 계층 (누락·변형 방지)

구현: [`verifier.py`](../apps/ebook_polisher/ebook_polisher/verifier.py), [`coverage_gate.py`](../apps/ebook_polisher/ebook_polisher/coverage_gate.py).

- **Chunk Plan 검증**: missing / duplicate_primary / overlap_only / coverage_ratio.
- **Polished Block 검증**: source_block_ids ⊆ output_block_ids (missing/extra 0).
- **Semantic Preservation**: 핵심 명사·숫자·고유명사·인용·수식·단위 보존률, 길이 급감 경고.
- **금지 변경 검사**: 숫자/날짜/인명/지명/논문제목/직접인용/수식/코드/ISBN/URL/각주번호 변경 차단.
- **Coverage Gate**: 단계별 페이지 수 전수 일치. 불일치 시 다음 단계·출력 차단.

## 8. 다중 에이전트 오케스트레이션 (v2 통합)

구현: [`agents.py`](../apps/ebook_polisher/ebook_polisher/agents.py), [`scheduler.py`](../apps/ebook_polisher/ebook_polisher/scheduler.py).

- **7-Agency**(A/B/C 논리·팩트, E 정직성, F 응축, G 윤문, J 집행관)가 블록/청크 단위로 토론·합의.
- **정직 봉인**: `★`(확신)/`◑`(주의) 마커를 `PolishedBlock.honest_marker`에 기록. 인간은 `◑`만 결재.
- **CID Scheduler**: 작업을 의존성 DAG(`TaskNode.dependencies`)로 보고, `ready_tasks`만 골라 **병렬 실행**. 청크 간 독립 작업은 동시 처리, 의존(크로스레퍼런스) 작업은 순서 보장.
- **Memory Router**: `0.35·유사도 + 0.20·중요도 + 0.15·최신성 + 0.15·장관련성 + 0.10·핀고정 + 0.05·검증신뢰`로 전역 기억 상위 N개 주입.
- **Prompt Gene Selector**: 토큰 예산 내에서 장르/작업 적합 프롬프트 조각을 점수순 선택.
- **엔진 모드**: `rules`(결정적·오프라인, 기본) / `v2_multiagent`(LLM·AutoGen 옵트인). 기본은 오프라인에서 무손실 동작.

## 9. 일관성 유지

- **전역 메모리 3종**: 정적(사용자 규칙)·추출(자동 추출 인물/개념/수식)·누적(확정된 문체/용어 결정).
- **Consistency Pass**: 인물/개념명 변형, 말투 흔들림, 제목·각주·수식 번호 불일치, 약속·회수 누락, 시간축/기호 충돌 검사.
- **Style Drift Detector**: 청크별 문체 벡터(평균 문장길이·종결어미 분포·한자어/외래어 비율·접속사 빈도·수식어 밀도·대화문 비율) 계산, 평균에서 크게 벗어나면 재윤문.

## 10. 무결성·복원력

- **재개 가능**: 모든 단계 상태를 저장. 실패 후 누락 block만 재처리. (`repository.is_done` 멱등)
- **실패는 정상**: API 백오프, JSON 파싱 실패 시 구조화 재시도, coverage 실패 시 누락만 재처리, drift 실패 시 style repair, 수식/표 손상 시 원문 보존 모드.
- **감사 추적**: 입력/중간/최종 해시 + AuditEvent + (옵션) OpenTelemetry trace.

## 11. 출판 전 QA 14게이트

① 페이지 수 ② block 수 ③ block_id 전부 출력 ④ 숫자 변경 없음/승인만 ⑤ 고유명사 보존/용어집 승인 ⑥ 직접 인용 보존 ⑦ 수식·코드·표 무손상 ⑧ AI 프롬프트 잔재 없음 ⑨ Markdown/HTML 태그 잔재 없음 ⑩ 중복공백·깨진 특수문자 없음 ⑪ 장/절 제목 누락 없음 ⑫ EPUB spine 순서 ⑬ DOCX heading 정상 ⑭ 최종 해시·감사 저장.
+ v1 **600 체크리스트 complete** + v2 **Hard-Fail 0**.

## 14. 검증 기준 (DoD)

- 합성 1000+페이지 원고에서 **page/block coverage 100%**, 누락 0.
- 결정적 `rules` 모드: 동일 입력 → 동일 출력.
- 금지 변경(숫자/고유명사/인용/수식) 보존 테스트 통과.
- 중단→재개 시 이미 처리된 청크 재실행 0(멱등).
- Hard-Fail·600 체크리스트·QA 14게이트가 출력 전 강제됨.
